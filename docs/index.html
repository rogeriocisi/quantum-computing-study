From Classical Code to Quantum Circuits

Why a software engineer would move from classical to quantum computing, how to go about it, and where the field meets AI.

Rogerio Cisi · November 2026 · 11 min read

Three questions come up whenever a working programmer looks at quantum computing. Is it worth the effort for someone who is not a physicist? If so, what is a realistic way in? And how does it relate to the other field reshaping software, artificial intelligence? This article takes them in turn, and uses a public study repository, quantum-computing-study, as the worked example.

Why make the move

A quantum computer is not a faster classical computer. It is a different model of computation, in which a register of qubits holds a vector of complex amplitudes, gates rotate that vector, and a measurement samples from it. For most everyday workloads this offers nothing. For a small set of problems it changes what is feasible, and that set is the first reason to pay attention.

The problems are specific and valuable. Shor's algorithm factors integers in polynomial time, where the best known classical methods take super-polynomial time. Grover's algorithm searches an unstructured space with quadratically fewer queries. Simulating molecules and materials, which are quantum systems to begin with, is the application the field was first proposed for. None of these is a general speed-up, and knowing exactly where the advantage comes from is most of what there is to learn.

The security consequences have already arrived. A large fault-tolerant quantum computer running Shor's algorithm would break RSA and elliptic-curve cryptography. No such machine exists yet, but encrypted data captured today can be stored and decrypted later, so the migration has started: NIST published its first post-quantum cryptography standards in August 2024.1 Engineers will be doing that migration whether or not they ever write a circuit, and it is easier to reason about when you have built the algorithm that motivates it.

Much of the remaining work is software. Between an algorithm on paper and a result from a device sits a stack that looks familiar: compilers that map circuits onto a chip's connectivity, optimizers that shorten them, runtimes that schedule jobs, layers that mitigate and correct errors, and the orchestration that ties quantum calls to classical code. The main toolkits are open source and written in Python. Testing, API design, performance work and continuous integration are all needed here, and they are skills software engineers already have.

The cost of entry is low. No laboratory is required. A statevector simulator on a laptop handles circuits of twenty-odd qubits, which is enough for every textbook algorithm; memory doubles with each added qubit and reaches about 16 GB at thirty. Cloud providers offer access to real devices, some of it free.

The honest counterweight. Today's devices are noisy, and no one has yet shown a quantum computer beating classical methods on a commercially useful problem. When that will happen is uncertain. The case for learning now is that the model takes time to absorb, the tools are mature enough to learn on, and the knowledge pays off in adjacent work such as cryptography, simulation and optimization even before the hardware arrives.

How to make the move

The path below is the one the repository follows: a 12-month plan at six to ten hours a week, ordered so that each step depends only on the ones before it.

  1. Start with linear algebra, not physics. Complex vectors, inner products, unitary matrices, tensor products and eigenvalues are the whole prerequisite. A qubit is a unit vector with two complex entries, a gate is a unitary matrix, and n qubits live in a space of 2n dimensions. Anyone who has worked with machine-learning code has seen most of this already.
  2. Learn the circuit model on small protocols. A Bell pair, teleportation, superdense coding and the CHSH game each fit in two or three qubits and each isolate one idea about entanglement and measurement.
  3. Work through the canonical algorithms in dependency order. Deutsch–Jozsa and Bernstein–Vazirani teach oracles and phase kickback. Simon introduces period finding. Grover adds amplitude amplification. The quantum Fourier transform and phase estimation then lead directly to Shor.
  4. Implement each one from scratch and test it against theory. If theory says a search should succeed 94.5% of the time, a test can check that it does.
  5. Move to hybrid, variational algorithms. Here a classical optimizer tunes the parameters of a quantum circuit. This is where quantum computing overlaps with machine learning, covered below.
  6. Then face noise. Noise models, error mitigation and runs on real hardware come last, once it is clear what the right answer should have been.
  7. Use a certification as a forcing function. The repository targets IBM's Qiskit developer exam (C1000-179), which gives the plan a syllabus and a deadline.

For materials, the repository's resource guide recommends Thomas Wong's Introduction to Classical and Quantum Computing as a first book, John Watrous's course Understanding Quantum Information and Computation for rigor, the Qiskit documentation for practice, and Nielsen and Chuang as the reference to grow into.

The transition is partly a matter of reusing habits and partly of unlearning assumptions:

Carries over

  • Python and its tooling, since the main SDKs are Python libraries.
  • Testing and continuous integration.
  • Modular design: oracles, diffusers and adders are reusable components.
  • Complexity analysis, which is how quantum advantage is stated.
  • Linear algebra from graphics or machine learning.

Has to be relearned

  • State cannot be copied, and on hardware it cannot be inspected mid-run. There is no print statement.
  • Every gate is reversible, so scratch results must be uncomputed, not discarded.
  • Output is a probability distribution. Tests assert on frequencies within a tolerance, not on single values.
  • An algorithm works by arranging interference so that wrong answers cancel.
  • Conventions bite: Qiskit orders bits little-endian, so strings are reversed when building oracles.

The roadmap in practice

quantum-computing-study is two things in one repository. It is a 12-month, part-time study plan (six to ten hours a week) for moving from classical software engineering to quantum development, aimed at IBM's Certified Associate Developer – Quantum Computation using Qiskit v2.X exam (C1000-179). And it is the laboratory where that plan is carried out: each algorithm on the syllabus is written from scratch in Python, documented, and put under test.

The premise is that reading about a quantum algorithm and being able to build it are different skills. A circuit that returns the right bitstring in a simulator, with a test that fails when it stops doing so, is a stricter check on understanding than a page of notes.

What is implemented

The first three phases of the roadmap cover foundations, query algorithms, and the phase-estimation family that ends in Shor's algorithm. All of them run on the local Qiskit Aer simulator through the SamplerV2 primitive. The table lists each one with the result of running its demo.

Two pieces worth a closer look

Shor's algorithm. The implementation follows the textbook structure: cheap classical checks first, then a phase-estimation circuit with an eight-qubit counting register and a four-qubit work register, then continued fractions to turn the measured phase into the order r, and finally a greatest-common-divisor step to extract a factor. For 15, every base from 2, 4, 7, 8, 11 and 13 yields 3 or 5, and the test suite also factors 21.

One shortcut is deliberate and should be read as such. The controlled modular multiplication is built as a permutation matrix handed to Qiskit as a unitary, not as a gate-level arithmetic circuit. That is fine for validating the algorithm on a simulator, but the matrix grows exponentially with the size of the number, so it is not how the algorithm would be run at scale.

The VBE adder is the other half of that story. It builds addition out of CARRY and SUM blocks made only of Toffoli and CNOT gates, uses 3n + 1 qubits for n-bit operands, and runs a backward pass that uncomputes the carry ancillas so they finish in the state they started in. It has the heaviest test coverage in the repository, including a check that the inverse CARRY block is the exact reverse of the forward one. Reversible arithmetic of this kind is the building block a gate-level modular exponentiation would need.

Engineering habits carried over

The repository treats quantum code as ordinary software. Each module starts as a short specification in docs/system/specs/, is implemented in src/, and gets a matching test file. Functions carry type hints and docstrings. Code is formatted with Black and linted with Flake8, and a GitHub Actions workflow runs the suite on Ubuntu and Windows across Python 3.10 to 3.12.

Everything targets the Qiskit 2.x API. Circuits are transpiled and executed through SamplerV2, the same primitive interface IBM's cloud runtime exposes, so switching from the simulator to a real backend is a change of execution target and not a rewrite. A small script, scripts/capstone_demo.py, already does this for a three-qubit GHZ state behind a --cloud flag.

What simulation does not tell you

All results above come from a noiseless simulator. On today's hardware, gate errors and decoherence accumulate with circuit depth, and a circuit as deep as Shor's returns mostly noise without error mitigation. The repository is explicit about this and takes a simulator-first approach: establish that the algorithm is correct, then deal with noise as its own subject later in the roadmap.

Not finished yet. Three modules exist only as skeletons with placeholder logic: the VQE and QAOA optimization workflow, the variational classifier built on PennyLane, and zero-noise extrapolation. They mark where phases four to six will land, and their current outputs are mock values.

Where quantum computing meets AI

The two fields are connected in three ways, and they are worth keeping apart because their maturity differs a great deal.

Quantum circuits as machine-learning models

A circuit whose gates take adjustable angles is a parameterized function, and it can be trained like one. The loop is the one every machine-learning engineer knows: run the model, compute a loss, estimate gradients, let a classical optimizer update the parameters, repeat. Gradients can be obtained from the device itself, since for common gates the derivative with respect to an angle follows from two extra runs of the circuit at shifted values.2 Libraries such as PennyLane make a circuit differentiable in the same sense as a neural-network layer and connect it to standard frameworks.

The same pattern, under different names, covers most near-term algorithms. A variational classifier encodes data into rotation angles and trains the remaining gates. The variational quantum eigensolver (VQE) minimizes the energy of a molecule. QAOA does the same for combinatorial problems such as Max-Cut. Quantum kernel methods use a circuit to define a feature space for a classical support-vector machine.3

What this has delivered so far should be stated carefully. There is no demonstrated practical advantage for quantum models on classical data. Training can stall on barren plateaus, where gradients vanish exponentially as circuits grow.4 Loading classical data into a quantum state is itself costly. And some proposed speed-ups have been matched by new classical algorithms inspired by the quantum ones.5 The strongest case remains data that is quantum to begin with, as in chemistry and materials.

AI as a tool for building quantum computers

The reverse direction is the one producing results today. Error correction needs a decoder that infers, in real time, which errors occurred from indirect measurements; in 2024 a neural-network decoder outperformed the leading conventional decoders on data from a real processor.6 Reinforcement learning is used to route and shorten circuits during compilation, machine learning helps calibrate and control devices, and code assistants trained on quantum SDKs help write the programs. Making quantum hardware usable is, to a large extent, an optimization and inference problem, which is what current AI is good at.

Shared foundations

Both fields are applied linear algebra in very high-dimensional spaces, both lean on gradient-based optimization, and both run on the same hardware: simulating a circuit is a sequence of matrix operations that a GPU accelerates in the same way it accelerates a neural network. Someone arriving from machine learning will find the variational half of quantum computing familiar. Someone arriving from software engineering will find it is the part where both worlds use one workflow.

In this repository

Phases four and five of the roadmap are devoted to this overlap: a variational classifier in PennyLane benchmarked against a classical baseline, then QAOA and VQE. As noted above, these modules are skeletons at the time of writing.

AI also shaped how the repository is built. Its process documents are written to be read by an AI coding assistant as well as by a person: a specification comes first, the implementation must follow it, and every module needs tests that check mathematical correctness in simulation. In a field where a plausible-looking circuit can be quietly wrong, a test that compares measured counts with the value theory predicts is the check that matters, whoever wrote the code.

What comes next

  • Quantum machine learning (months 4–5): variational circuits trained with PennyLane and compared against a classical baseline.
  • Optimization (months 6–7): QAOA on Max-Cut and VQE on small molecules such as H2.
  • Capstone (months 8–10): a complete hybrid application with realistic noise models, error mitigation, and a run on cloud hardware.
  • Certification (months 11–12): review, mock exams, and the C1000-179 exam.

The full week-by-week plan is in the roadmap document, and the dashboard gives a visual summary. Each algorithm also has a reference note with the mathematics behind the code.

Running it yourself

Clone the repository, install requirements.txt into a virtual environment, and run python -m pytest. Each algorithm is also runnable as a module, for example python -m src.algorithms.shor. The code is released under the MIT license.
